1. Memory Hierarchy & Address Spaces
Memory Hierarchy & Latency
  • Speed Order: Registers (<1ns) > L1/L2/L3 Cache (1-10ns) > RAM (50-100ns) > SSD/NVMe (μs) > HDD (ms).
  • Resident Monitor: Early OS batch prototype; uses Fence Register to isolate OS code from user programs.
  • Logical (Virtual) Address: CPU generates at execution.
  • Physical (Real) Address: RAM hardware pin address.
Address Binding: 3 Crucial Phases
  • Compile Time: Generates Absolute Code. Starting address fix hota hai; move karne par scratch recompile!
  • Load Time: Generates Relocatable Code. Offset relative to 0; loader final RAM base address bind karta hai.
  • Execution Time: Dynamic relocation via hardware MMU. Process runtime par RAM me swap/relocate ho sakta hai.
Physical Addr = Logical Addr + Base Register
2. Dynamic Loading & Linking
Dynamic Loading
  • Routines memory me tabhi aate hain jab unhe actually call kiya jaye (on-demand). Unused error routines memory waste nahi karte.
Dynamic Linking (Shared Libs .so / .dll)
  • Binary me actual code ke bajaye chhota Stub embed hota hai. Shared library RAM me ek baar load hoti hai aur sabhi share karte hain.
3. Contiguous Allocation, Fragmentation & Strategies
Fixed vs Variable Partitions
FeatureFixed (MFT)Variable (MVT)
PartitioningBoot time fixed slotsDynamic on process request
MultiprogrammingStrictly partition countDynamic (RAM capacity)
FragmentationInternal FragmentationExternal Fragmentation
  • Internal Frag: Partition space unused by smaller process.
  • External Frag: Total free memory sufficient hai par non-contiguous hone se allocation fail ho jati hai (50% Rule).
  • Compaction: Processes ko relocate karke ek bada hole banana; requires Execution-Time Relocation!
Dynamic Storage Allocation Strategies
  • First Fit: Pehla hole jo process size satisfy kare. Sabse Tez (Fastest), shuru me chhote fragments chhodta hai.
  • Best Fit: Smallest hole jo satisfy kare. Badi holes preserve rehti hain par smallest useless slivers create hote hain (Worst external frag). O(n).
  • Worst Fit: Sabse bada available hole allocate karo. Leftover hole bada rehta hai, par largest blocks jaldi exhaust hote hain. O(n).
  • Next Fit: Circular First Fit from last allocation pointer.
Hardware Bounds: If L < Limit ⇒ Base + L; Else Trap!
4. Non-Contiguous Paging & Address Translation
Paging Principles & Address Math
  • RAM is split into Frames; Process is split into Pages.
  • Invariant: Frame Size = Page Size = 2^n bytes.
  • External Fragmentation = ZERO (Completely eliminated!)
  • Internal Fragmentation: Last page only (Avg = PageSize / 2).
  • Logical Address = [p : m - n bits] | [d : n bits].
  • Page Table index p yields Frame f ⇒ Physical = [f || d].
Physical Addr = (f × FrameSize) + d
Pure Paging Latency Bottleneck
  • Pure paging me har access ke liye RAM ko DO BAAR access karna padta hai:
  • 1. Page Table entry read karne ke liye (RAM access 1).
  • 2. Actual data / instruction read karne ke liye (RAM access 2).
  • Latency penalty = 100% Slowdown (2 × t_RAM).
Pure Paging Access Time = 2 × t_RAM
5. TLB (Translation Lookaside Buffer) & EMAT
Hardware Associative Cache & Effective Memory Access Time (EMAT)
  • TLB: High-speed associative cache on CPU chip (1-10ns). Fast parallel search for <p, f>.
  • TLB Hit (h): Time = t_TLB + t_RAM. Direct physical frame read.
  • TLB Miss (1 - h): Time = t_TLB + 2 × t_RAM. Read table from RAM, update TLB, then read data.
EMAT = h(t_TLB + t_RAM) + (1-h)(t_TLB + 2×t_RAM)
EMAT = t_TLB + (2 - h) × t_RAM
  • Solved Quick: If t_RAM=100ns, t_TLB=20ns, h=0.8 ⇒ EMAT = 0.8(120) + 0.2(220) = 140 ns. (At h=0.98 ⇒ 122 ns).

6. Multilevel & Inverted Page Tables
Two-Level Hierarchical Paging
  • 32-bit CPU with 4KB pages needs 1M entries × 4B = 4MB contiguous table per process!
  • Two-Level Split: [p1 : 10 bits] | [p2 : 10 bits] | [d : 12 bits].
  • Outer page table fits in 1 page (4KB). Unused inner tables RAM me load nahi hote (huge RAM savings!).
  • Miss Penalty: k-level paging me miss par (k + 1) RAM accesses lagte hain (Two-level = 3 RAM accesses).
Inverted Page Table
  • Poore system me strictly EK TABLE hoti hai, indexed by physical Frame Number i.
  • Entry = <Process ID (PID), Page Number (p)>.
  • Pro: Memory overhead physical RAM ke size par depend karta hai, virtual space par nahi (Extremely small).
  • Con: Slow search (requires Hash Table); shared memory difficult.
7. Segmentation & Paged Segmentation
Segmentation Architecture <s, d>
  • User/Programmer view: Variable size modules (Code, Stack, Heap).
  • Segment Table: Stores Base (physical start) and Limit (length).
  • Hardware Bounds Check:
    • If (d ≥ Limit) ⇒ TRAP: Segmentation Fault!
    • If (d < Limit) ⇒ Physical Addr = Base + d.

8. Virtual Memory & Demand Paging
Demand Paging & Valid-Invalid Bit
  • Virtual memory allows process size > physical RAM.
  • Demand Paging: Pages loaded into RAM only when demanded by CPU (Lazy Swapper / Pager).
  • Page Table (V/I) Bit:
    • 'v' (Valid = 1): Page is physically in RAM.
    • 'i' (Invalid = 0): Page is not in RAM (On disk swap space).
  • Accessing invalid page triggers PAGE FAULT TRAP!
6-Step Page Fault Handling Sequence
  1. MMU detects 'i' bit ⇒ Hardware Trap to OS.
  2. OS kernel saves user registers & state into PCB.
  3. OS checks legality; if legal, finds free frame in RAM.
  4. Issue disk I/O to swap-in page from backing store.
  5. Write frame # in Page Table; flip bit to 'v' (Valid).
  6. OS restarts trapped instruction from exact PC point.
9. Effective Access Time (EAT) under Demand Paging
EAT = (1 - p) × t_RAM + p × (Fault Service Time)
  • t_RAM = 100 - 200 ns | Fault Service Time = 8 - 10 ms (8,000,000 ns).
  • Disk access is 100,000× slower than RAM!
Numerical Rule of Thumb:
  • For < 10% performance degradation: $$p \le rac{\Delta ext{Allowed Time}}{ ext{Fault Time}} pprox rac{20 ext{ns}}{8 imes 10^6 ext{ns}} = rac{1}{400,000} = \mathbf{0.00025\%}$$
  • System must have fewer than 1 fault per 400,000 references!
10. FIFO Page Replacement & Belady's Anomaly
FIFO Algorithm & Dirty Bit
  • FIFO: Replaces oldest page in RAM. Implemented via circular queue.
  • Dirty (Modify) Bit: If 0 (Clean) ⇒ discard without disk write; If 1 (Dirty) ⇒ must write back to swap space before evicting.
Belady's Anomaly Proof (AKTU Classic)
  • Phenomenon: Frames badhane par page faults badh jate hain!
  • String: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
  • 3 Frames ⇒ 9 Page Faults.
  • 4 Frames ⇒ 10 Page Faults! (Faults Badh Gaye)
  • Why: FIFO is NOT a Stack Algorithm ($S_n ot\subseteq S_{n+1}$).

11. Optimal & LRU Page Replacement (Stack Algorithms)
Optimal (OPT / MIN) Algorithm
  • Rule: Replace page that will not be used for longest time in future.
  • Guarantees lowest possible page fault rate.
  • Theoretical benchmark; impossible in real OS (needs future oracle).
  • No Belady's Anomaly (Stack Algorithm).
Least Recently Used (LRU) Algorithm
  • Rule: Replace page that has not been used for longest time in past.
  • Approximates OPT via temporal locality. No Belady's Anomaly!
  • Implementation:
    • 1. Logical Clock Counter: Min counter value victim ($O(n)$ search).
    • 2. Doubly Linked Stack: Most recent to Top; Bottom = victim ($O(1)$).
12. Clock (Second Chance) & Counting Algorithms
Second Chance (Clock) Replacement
  • Circular queue + Clock Pointer + Reference Bit (R).
  • If R == 0 ⇒ Replace page (Victim found!).
  • If R == 1 ⇒ Reset R = 0, advance pointer (Second chance!).
  • Degenerates to FIFO if all bits are 1.
Enhanced Clock & Counting (LFU/MFU)
  • Enhanced Pair <R, M>: (0,0) Best victim > (0,1) Dirty > (1,0) Clean recent > (1,1) Worst candidate.
  • LFU: Smallest reference count replaced.
  • MFU: Highest count replaced (protects new arrivals).
13. Thrashing & Working-Set Model
Thrashing Cause & Working-Set Model
  • Thrashing: CPU utilization crashes near 0% because system spends 99% time swapping pages between disk and RAM.
  • Root Cause: High Degree of Multiprogramming ⇒ Frames per process fall below locality ⇒ continuous faults.
  • Working-Set Model: Parameter $\Delta$ (Window).
    • $WSS_i$ = pages accessed in last $\Delta$ refs.
    • Demand $D = \sum WSS_i$.
    • If D > Total Frames M ⇒ Thrashing occurs!
Page-Fault Frequency (PFF) Strategy
  • Dynamic self-regulating frame allocation.
  • If Fault Rate > Upper Threshold ⇒ Allocate extra frames to process.
  • If Fault Rate < Lower Threshold ⇒ Remove surplus frames from process.
  • If Upper exceeded and no frames free ⇒ Swap-out process.
14. Locality of Reference & Cache Organization
Locality of Reference
  • Temporal Locality: Same location accessed again soon (Loops, loop index counters, subroutines).
  • Spatial Locality: Adjacent memory locations accessed soon (Array sequential access, code stream).
Cache Mappings & AMAT
  • Direct: Line = Block mod N. Fast, high conflict misses.
  • Fully Associative: Any block in any line. Zero conflict.
  • k-Way Set: Set = Block mod NumSets. Best balance.
AMAT = Hit Time + (Miss Rate × Miss Penalty)
