1. Functional Dependency (FD: X → Y) Schema Invariant

Formal Rule: In relation R, X → Y holds iff ∀ tuples t1, t2 ∈ R:
If t1[X] = t2[X] ⇒ t1[Y] MUST equal t2[Y].

Determinant: X (LHS) ──[Decides]──> Dependent: Y (RHS)
  • Instance vs Schema: FD schema rule hota hai, data ke coincidence par depend nahi karta!
  • Closure Property: Har relation instance me integrity enforce karta hai.

3. Armstrong's Axioms (Sound & Complete Axiomatic Inference System) F⁺ Generation
Primary Axiom 1: Reflexivity
If Y ⊆ X ⇒ X → Y
Subset property: Har attribute set apne sub-parts ko trivially determine karta hai.
Primary Axiom 2: Augmentation
If X → Y ⇒ XZ → YZ (∀ Z)
Additive property: Dono taraf koi bhi attribute jod sakte hain.
Primary Axiom 3: Transitivity
If X → Y & Y → Z ⇒ X → Z
Chaining property: Dependency aage chain banakar transfer hoti hai.
Derived 4: Union / Additive
X → Y & X → Z ⇒ X → YZ
LHS same ho toh RHS combine ho sakta hai.
Derived 5: Decomposition
X → YZ ⇒ X → Y & X → Z
RHS split hota hai. LHS KABHI split nahi hota!
Derived 6: Pseudo-Transitivity
X → Y & WY → Z ⇒ WX → Z
Useful for proving implied dependencies.
Soundness: Derived FD hamesha physically valid hogi. | Completeness: Saari logically implied FDs (Closure F⁺) nikal aayengi.
4. Attribute Closure Algorithm (X⁺) Polynomial O(|F|·|R|)
  1. Init: Set closure = X.
  2. Loop: Repeat for each Y → Z ∈ F:
    If Y ⊆ closure, then closure = closure ∪ Z.
  3. Fixed-Point: Loop tab tak chalao jab tak koi naya attribute add na ho. Return closure as X⁺.
Key Applications:
• Check if A → B holds: Test if B ⊆ A⁺.
• Super Key Test: Check if X⁺ contains ALL attributes (X⁺ = R).

6. Equivalence of FD Sets (F ≡ G) F⁺ = G⁺ Test

Do sets F aur G tabhi equivalent hote hain jab dono ek doosre ko cover karein:

  • Test 1 (G covers F): ∀ X → Y ∈ F, check if Y ⊆ X⁺_G.
  • Test 2 (F covers G): ∀ A → B ∈ G, check if B ⊆ A⁺_F.
Both tests pass ⇒ F ≡ G. Polynomial time verification!
7. Canonical Minimal Cover (Fc) 3-Step Method Irreducible Set
  1. Singleton RHS: Break X → ABC into X → A, X → B, X → C.
  2. Remove Extraneous LHS: In AB → C, if C ∈ (A)⁺ without B, drop B!
  3. Remove Redundant FDs: For each X → Y, test if Y ∈ X⁺_(F - {X→Y}). If YES, delete!
8. The 3 Database Anomalies Root: Redundancy
  • Insertion Anomaly: Cannot insert an independent entity without a primary key (NULL not allowed).
  • Deletion Anomaly: Deleting one tuple inadvertently destroys unrelated secondary entity data.
  • Update Anomaly: Redundant copies cause data inconsistency if some rows fail to update.
9. First Normal Form (1NF) Atomic Values

Rule: All attribute domains must contain strictly atomic (indivisible) values.

  • Eliminate Multi-valued attributes (lists/arrays in cells).
  • Decompose Composite attributes (Address → City, PIN).
  • Eliminate Repeating groups (numbered columns like Skill_1, Skill_2).

11. Special Theorem: Simple Candidate Keys Speed Shortcut

Theorem: Agar kisi relation ke sabhi candidate keys Single Attribute (Simple) hain, toh wo relation AUTOMATICALLY 2NF me hota hai!

Proof: Single attribute ka koi non-empty proper subset nahi hota, isliye partial dependency mathematically impossible hai!
12. The Great 3NF vs BCNF Trade-Off Industry Standard
  • 3NF: Always guarantees Lossless Join AND Dependency Preservation. Slight redundancy allowed.
  • BCNF: Eliminates ALL functional redundancy, but MAY LOSE functional dependencies!

13. Lossless Join (Non-Additive) Decomposition Mandatory R = R1 ⋈ R2

Binary Decomposition Theorem: Split of R into R1, R2 is Lossless iff:

(R1 ∩ R2) → R1 OR (R1 ∩ R2) → R2

Intuition: Common attribute set MUST be a Super Key in at least one table!

If this condition fails ⇒ Spurious Tuples (fake records) appear upon natural join!
14. Dependency Preservation Property (F1 ∪ ... ∪ Fk)⁺ = F⁺

Decomposition is dependency preserving if all original constraints can be checked within individual tables without executing expensive cross-table joins.

  • Fi = π_Ri(F) = { X → Y ∈ F⁺ | XY ⊆ Ri }
  • 3NF: Always preserves all FDs (✓).
  • BCNF: May not preserve some FDs (✕).
15. Multivalued Dependencies (MVD) & 4NF Independent Multi-Facts

MVD Definition (X ↠ Y): Y values associated with X are independent of Z values. Causes m × n Cartesian explosion!

t1[X]=t2[X] ⇒ ∃ t3, t4 with swapped Y and Z coordinates

4NF Condition: Relation in BCNF, and ∀ non-trivial X ↠ Y:
X MUST BE A SUPER KEY OF R.

Fagin's Split: R(X,Y,Z) decomposes into R1(X,Y) and R2(X,Z).
16. Join Dependencies (JD) & 5NF (PJNF) Ultimate Projection Form

Join Dependency: ⋈[R1, R2, ... Rn] holds if R = ⋈ π_Ri(R). Models 3-way cyclic relationships.

5NF Condition: In 4NF, and for every non-trivial JD:
EVERY Ri MUST BE A SUPER KEY OF R.

Inclusion Dependency (IND): R[X] ⊆ S[Y].
Theoretical foundation of Foreign Key & Referential Integrity!
17. Universal AKTU 10-Mark Normalization Solving Algorithm Guaranteed Full Marks

Step 1: Find All Candidate Keys

  • Partition attributes: Cat A (Never RHS), Cat B (Both), Cat C (Never LHS).
  • Compute (Cat A)⁺. If equal to R ⇒ Unique Candidate Key!
  • If not, combine with Cat B singles/pairs. Identify Prime vs Non-Prime.

Step 2: Test 2NF (Partial Dependency)

  • Is any Non-Prime attribute determined by a proper subset of CK?
  • If YES ⇒ Violates 2NF (Highest NF = 1NF). Decompose into R1(X', Y) & R2(R - Y).

Step 3: Test 3NF (Transitive Dependency)

  • For every X → Y: Is X a Super Key? OR Is Y a Prime Attribute?
  • If neither holds ⇒ Violates 3NF. Highest NF = 2NF. Decompose via Bernstein.

Step 4: Test BCNF (Strict Super Key)

  • For every X → Y: Is X strictly a Super Key?
  • If NO ⇒ Highest NF = 3NF. Decompose R into R1(X ∪ Y) & R2(R - Y).
