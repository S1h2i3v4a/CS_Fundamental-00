1. Concurrency Control Overview & Motivation

Concurrency Control Manager ensures Isolation and Consistency across concurrent transactions. Without proper synchronization, interleaved operations cause Dirty Reads, Lost Updates, and Unrepeatable Reads.

2. Binary vs Shared/Exclusive (Read/Write) Locks

Binary locks allow only 1 transaction per item (0 = Unlocked, 1 = Locked), severely bottlenecking throughput. Two-Mode Locks support Shared mode S(X) for concurrent readers and Exclusive mode X(X) for writers.

Compatibility Rule
Shared locks are mutually compatible with other Shared locks. Exclusive locks are mutually exclusive with ALL locks.

4. Lock Manager Internal Operations

Lock Manager maintains a hash table of locks with transaction wait queues and reader count no_of_reads(X). Lock is fully released to unlocked state only when reader counter reaches 0.
