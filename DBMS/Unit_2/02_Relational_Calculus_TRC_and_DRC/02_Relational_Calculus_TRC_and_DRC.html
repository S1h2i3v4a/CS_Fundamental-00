Module 02: Relational Calculus (TRC and DRC)

Non-Procedural Power: Relational Calculus specifies WHAT data is needed using mathematical First-Order Logic, without specifying the procedural access path.

1. Tuple Relational Calculus (TRC)

Format: { t | P(t) }. Tuple variable t represents an entire row. Quantifiers ∃ (There exists) and ∀ (For all) allow joins and universal subset queries.

-- Find names of employees in 'Research' earning > 60000:
{ t.name | t ∈ EMPLOYEE ∧ t.dept = 'Research' ∧ t.salary > 60000 }

2. Domain Relational Calculus (DRC)

Format: { ⟨x1, x2, ...⟩ | P(x1, x2, ...) }. Variables represent individual column domains.

-- Find emp_id and name of employees in 'Sales':
{ ⟨e, n⟩ | ∃d, s (⟨e, n, d, s⟩ ∈ EMPLOYEE ∧ d = 'Sales') }
Safe Queries: Unsafe queries like { t | ¬(t ∈ R) } return infinite universes. A calculus expression is Safe if all resulting values are bounded within the active domain of the database.

3. Codd's Theorem

Equivalence: Relational Algebra ≡ Safe TRC ≡ Safe DRC. Any database query language matching this power is termed Relationally Complete.
